## 57 Home (Today)

**Status:** Changed from V2 (Home and the Chat screen reached from it).

**Why:** the partner opens BlueAI to check one thing: is my worker on, did today happen, did the days count, is anything waiting for me. V2's home is the chat's empty state: 'Hi, Alex' with an emoji and "You're all set. The BlueAI worker is all it takes to start earning." above a coach that says 'Run this to begin' (`chat_product.jsx:204-213`); since 2026-10-14 that one line greets returning partners too, and the progress strip left home for the partner dashboard (`moneymaker_home.jsx:102-104`), so home says nothing about the days. The chat itself unmounts on any other tab (`index.html:975`), taking a waiting job or a Retry with it.

### Home

- **Purpose:** today at a glance, answered from the Worker record (section 41), with the one action that matters now.
- **Anatomy:** inside `ScreenFrame` (AppFrame + TopBar + BottomNav, Home lit). ScreenHeader as the greeting: 'Hi, Alex' (the account's first name; 'Today' when there is none; no emoji, no second line). Then `.v2-screen-body` (padding 16 16 24, blocks 12 apart, the only part that scrolls): WorkerCard (section 42), ProgramStrip (section 43), a Banner only for a program fact the card cannot say, and one standalone Link 'Chat with BlueAI' (13/500, 32 target, left aligned). The top bar's run chip and credits come from `topBarProps(record)`, which maps the record to section 30's RUN_STATUS: 'Next run 11 am', 'Next run 9 am to 8 pm' (a run window), 'Runs later today' (Any time), 'Running', 'Needs you', 'Day 7 of 20' (the blue pending ring until verified; green only for verified and complete), 'Not counted today', 'Didn’t finish', 'Stopped', 'Didn’t start', 'Can’t run', 'Paused', 'Offline', 'Waiting for credits' (only while the refill lands before 9 pm; when it lands after, `creditsDay` 'stopped', the chip says 'Not counted today'), 'Period ended', 'All 20 days done' (section 30's table). The credits chip warns only until today's run is done. Activity carries the section 54 badge: a waiting job, a failed, stopped, missed or blocked run, and the latest day not counted (rejected); never Home.
- **Variants:** one screen; the content changes with the record. The only Banner: info 'You can still reach 17 of 20 days', a title with no body, only when `numbers().outOfReach` > 0 (proposed; the loss is said once, by the DayBar legend; no money until decision D3).
- **Actions:** Run opens setup in Chat for a new partner (Chat 'setup') and starts today's run otherwise (Chat 'running'); Review job opens the waiting ask (Chat 'waiting'); a failed day's Try again opens Chat 'retrying'; offline Try again reconnects in place (`onReconnect`; without one, a toast 'Still offline. BlueAI keeps trying on its own.'), and Home passes ScreenFrame `offlineBanner={false}`, since the card already says it (section 51); Resume calls `onResume`, and without one a toast says 'Daily runs are back on.'; a blocked run's fix does what its button says: Open App Player and Get BlueStacks act in place (`onFix`), Connect YouTube opens Connected apps.
- **Sizes:** window 419 x 830, compact 640 (bars pinned, body scrolls). Content column 387.
- **States (`state` prop, or derived from `worker`):** new (day 0: Set up card, the coach mark under it, nothing dimmed), returning before today's run ('Next run today at 11 am.', Run now secondary), running (live step), waiting for you (deadline and cost, Review job primary), done today pending (one tick, no second Run), done with no job (the day still counts, nojob), skipped (today doesn't count), day 20 done (the last day, pending, day20), failed today (reason, Try again by 9 pm), stopped (Run again by 9 pm), didn't start (the PC was off or asleep; Run now by 9 pm), can't run (one fix per reason), paused, out of credits (refresh time), offline (what happens to today), program complete (Earnings), period ended (section 69's SystemStates period-ended or period-under, not a card), out of reach (the banner), loading (the worker-home skeleton: a title, the worker card, the strip card, sized from `--v2-mark-lg`, `--v2-control-md` and `--v2-rail`; never V2's five-card skill list, `chat_product.jsx:222`). `HOME_STATES` adds nojob, skipped and day20 to the list above.
- **Props:** `worker`, `state`, `loading`, `coaching` (force the coach on or off), `onNavigate(id, opts)` (ids: `activity` from See why; the run chip and Details open `chipTarget(record)` (`screens/home.jsx`, section 30's Opens column): today as its Activity row opens it, `chat` {state} while live or `run` {state, row} once it has an outcome, `worker-settings` while paused, `home` otherwise; `chat` with `opts.state` from Run, Review job, Try again and the link; `credits`, `notifications`, `account`, `report`, `sign-out`; `connected-apps` {app: 'youtube'} from a blocked run's Connect YouTube (Open App Player and Get BlueStacks act in place through `onFix`). Every id is in section 32's route table), `onRun`, `onRetry`, `onReconnect`, `onResume`, `onFix`, `onDismissCoach`, `compact`, `landmark` (false in specimens), `frame` (false: content only).
- **Motion:** none of its own. The coach mark rises once (section 42); skeleton shimmer stops under reduced motion.
- **Accessibility:** the greeting is the screen's h1 and the focus target when the app returns to Home; the coach mark is a note; Okay or Run dismisses it; dismissal is stored on the record (`coachSeen`), never local state (`moneymaker_home.jsx:105`). Loading is `aria-busy` with a 'Loading your worker' status.
- **Responsive:** at 640 the header and bars stay put and the column scrolls; nothing reflows sideways.
- **Do / Don't:** Do read every number and time from the record; keep one card with one action; use the banner only while a program fact holds. Don't add a second greeting line that repeats the card; don't hide the strip until the partner has been back once; don't make Home the chat.

### Chat (from Home)

- **Purpose:** the thread as a window onto the same Worker record; leaving it loses nothing.
- **Anatomy:** ScreenHeader 'Chat' with Back (to Home) and a 32px IconButton 'New chat' (plus), moved out of V2's top bar (`index.html:350-355`). Thread (section 34) filling the height; today's run as one RunCard (section 36); a paid job as the JobPreviewCard (section 45), any other question as an AskCard (section 37); Composer (section 38) on the bottom edge with its notice slot. Home stays lit in the nav.
- **Variants:** `CHAT_STATES`: empty, setup, setupDone, running, waiting, done, nojob, skipped, day20, failed, retrying, noCredits (Short of credits), creditsZero, automatic, request, offTopic.
  - Setup follows V2's order (`worker_flow.jsx:65-171`): 'Welcome! Let’s set up your BlueAI worker.', the pitch, confirm @alexwatches, watch history (PermissionRequest, section 46), the run time, then paid jobs per app, Always ask first and Automatic only through ConsentDialog. The run time's window option is '9 am to 8 pm' (proposed; V2 '9am–9pm', `worker_flow.jsx:73-74`), since runs start by 8 pm (section 62); the schedule ask's hint is 'Pick one for now; change the time anytime in Settings > Worker.' No on the handle answers 'Okay. I can only use the YouTube account you applied with, or a channel under it. If you meant a different channel, report a problem and we’ll help.' with a Report a problem link (the sheet, topic 'My account or sign-in', section 65). It closes with ProgramSummary plus the D7 line: option A 'Your first run starts now, and today counts as day 1 once it’s verified.' (shown until the PM picks), followed by today's RunCard running, and the record says running; or B 'Your first counted day is tomorrow, at your run time.'
  - Waiting asks in the JobPreviewCard (section 45): the video, the channel, what will be done with the exact comment, and 'Answer by 9 pm or today won’t count.', which the run card then drops so it is said once. Answers: 'Take this job', 'Skip: today won’t count', and a quiet 'Switch YouTube to Automatic' through ConsentDialog; the answer shows as the partner's reply and the card settles (section 45's answered state). Option B, V2's words ('Paid job available', 'Watch the video and provide feedback.', 'Want me to take this one?', answers 'Yes' / 'Not now', `worker_flow.jsx:50-51, 115-119`) plus the R07 bullets in an AskCard, is `D17 = 'B'` in `screens/chat.jsx` (decision D17, section 73).
  - Any answer that turns Automatic on opens ConsentDialog first and answers only on 'I agree, turn on'; Cancel leaves the question waiting.
- **Sizes:** as Home. Bubbles max 300 (section 35).
- **States:** empty (EmptyState 'Chat with BlueAI' / 'Ask about today’s run, your days, or where to change a setting.'), running (field read-only, Send becomes Stop), waiting (the ask), retrying (the second try, live), failed (Try again by 9 pm), done (run card + See run details). Stop asks first while running, retrying or waiting (Composer `costsDay`, section 38). Out of credits says each fact once: the RunCard 'Not enough credits for this job.' + `OOC_COPY.day`; the field locks only at zero (creditsZero), where the OutOfCreditsNotice above it says until when and the locked field's placeholder is neutral, 'You can’t send messages right now' (section 48); short of today's run (noCredits, 120 of 360) the field stays open with the ComposerNotice 'Not enough AI credits for today’s run. They refresh at 5:30 am.' Automatic on (ComposerNotice info: 'Automatic is on for YouTube. BlueAI takes paid YouTube jobs without asking.' + 'Change', V2's ribbon words until 2026-10-14; V2 archived the ribbon the same day and shows the mode on the composer's chip).
- **Typed messages (proposed copy):** a status question is answered from the record ('Did today count?': 'Today’s run is done. Day 7 of 20, pending verification. We check every run within a day.'); an action request gets 'I don’t change settings from chat, so nothing has changed. You can set the run time in Worker settings.' plus a Link 'Open Worker settings'; out of scope gets 'That’s not something I can do here. I run your daily YouTube job, answer questions about your runs and days, and point you to the setting you need.' The worker never acts silently on typed text.
- **Props:** `worker`, `state`, `steps` (renderMessage shape), `onBack`, `onNewChat`, `onSend`, `onStop`, `onAnswer`, `onChangeMode`, `onOpenRun`, `onOpenCredits`, `onNavigate`, `compact`, `landmark`, `frame`.
- **Motion:** the thread's own (smooth jump to latest, none under reduced motion).
- **Accessibility:** the thread is a polite log; New chat and Back are labelled icon buttons at 32; the notice is tied to the field with aria-describedby.
- **Responsive:** the thread takes the height left between header and composer; the composer grows to 6 lines, then scrolls.
- **Do / Don't:** Do show a run as one card that updates in place; say what an answer costs before the tap (on the skip button itself); put a condition that holds before typing in the notice slot. Don't make the chat the only record of a run; don't put New chat in the top bar; don't let the partner type a message credits will refuse.
