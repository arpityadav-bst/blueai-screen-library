Modern Terminal — Design System

Every specimen on this page is the real component, rendered with the real class names from blueai-desktop.css — the same stylesheet the product links. Nothing is re-implemented here, so this page cannot silently drift from what ships. Token values are read live via getComputedStyle rather than typed in.

How the theming works. The 46 --bai-* tokens are declared on .drawer (dark) and .drawer.light, not on :root — deliberately, because the dormant marketing site in this same repo uses the same --bai-* namespace with entirely different values, and the scoping is what stops the two colliding. Component rules are plain global classes that resolve those vars, so a specimen outside a token scope would lose every colour. This page wraps each canvas in .bai-scope — a tokens-only alias declared alongside .drawer in the product stylesheet, so these swatches are the real values, not a copy.

Icons

Feather-style line icons, built by the product's own iconSvg(path, size) helper: fill:none, stroke:currentColor, stroke-width:1.8, round caps and joins, 24×24 viewBox. They inherit colour from their container, which is why the same glyph works on a card, a button, and an accent chip without variants. The paths live in blueai-icons.js, which both the product and this page read from — so the grid below is the complete real inventory, not a sample.

Two inconsistencies, recorded not tidied. close and closeAlt are two different paths for the same X glyph, both live today. chevron and search are authored in static markup at stroke-width:2 while iconSvg() uses 1.8 — so they render very slightly heavier in the product than in this grid. Unifying either is a product change.

The ✦ sparkle is deliberately not here: the product uses the text character, not an SVG, so it belongs to the type layer.

Two families by context. .bai-set-btn is the in-pane button (Settings, cards, screens); .bai-modalact is the in-modal action, taller and heavier because a modal asks for one decision. .hero exists so a screen's single conversion CTA matches the modal's weight instead of reading lighter just for living in Settings.

Credits & gauge

The credit ring is the product's one shared way of showing a balance — an SVG arc driven by stroke-dasharray, coloured by a ramp that steps blue → amber → orange → red as the balance drains (--bai-credit-hi/mid/low/crit). .lg is the same gauge at 60px for screen heroes. Because the header pill and the AI Credits screen share it, zooming from one to the other reads as the same number, not two dialects.

.bai-credit-ring .bai-credit-ring.lg14px inline (header) and 60px hero. The ramp colour carries urgency; the arc carries proportion.

Conventions

Rules that hold across the system — worth reading before adding anything.

house rules
1. A signal must earn its slot. Before adding a divider, badge, or tag, name what already signals that boundary — a label's own margin, a card's border, a colour/weight shift, or a neighbouring line of text. A second element restating the first is decoration.
2. Match the ROLE, not the look. Reuse a component because it does the same job, not because it resembles what you need. An accent-tinted card that happens to look right may be a chat-message bubble, not a pricing card.
3. Every control renders every state. Empty, filled, active, disabled, hover. An interaction state that's missing — or borrowed from an unrelated colour — is a worse signal than none.
4. One hero action per surface. Filled + .hero weight for the action you're recommending; outlined and slimmer for the escape hatch. The size difference is doing work.
5. Spacing is hierarchy. Tight within a group, generous between groups. Beware stacking a child's own margin against a parent's flex gap — they add, they don't override, and that's how a label ends up further from what it labels.
6. Both themes, every time. A recipe tuned by eye on dark can read dull or smudged on light (and vice versa). Check contrast, not vibes.
